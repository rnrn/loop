# Development loop

Работай только с одной текущей Story.

## Команды и границы

- `npm test` — тесты ТОЛЬКО активного этапа и всего пройденного до него.
  Это и есть твой гейт. Ориентируйся на него.
- `npm run trace` — какие acceptance criteria закрыты тестами, а какие
  проверяет человек. Критерии с пометкой «ручной сценарий» тестом не
  закрываются: не пытайся написать под них unit-тест.
- `npm run test:all` НЕ запускай. Он показывает будущие этапы, которые
  ещё не открыты; их провалы к твоей задаче не относятся.
- Активный этап переключает только модератор. Не трогай:
  `workshop.state.json`, `tools/`, `tests/`, `checkpoints/`.

Имена тестов начинаются с кодов критериев (`S1-03`, `S2-06`, `CR-06`).
Эти же коды стоят в Story — по ним сверяй, что закрыто, а что нет.

1. Прочитай SPEC.md, текущую Story, тесты и progress.md.
2. Запусти npm test и зафиксируй незавершённое состояние.
3. Внеси минимальное изменение для acceptance criteria.
4. Не реализуй будущие Stories и non-goals.
5. Запусти npm test.
6. При FAIL:
   - прочитай конкретную ошибку;
   - запиши первопричину;
   - исправь её;
   - повтори проверку.
7. При PASS:
   - сравни реализацию со всеми criteria;
   - выполни ручной сценарий;
   - запиши evidence в progress.md;
   - пометь Story как done.
8. Не переходи к следующей Story без команды модератора.

Terminal states:
- DONE — Story проверена и evidence записан.
- BLOCKED — отсутствует необходимый доступ или решение.
- RETRY_LIMIT — три попытки не устранили ошибку.
- TIMEBOX_EXPIRED — завершён лимит этапа.

Запрещено:
- изменять или ослаблять тесты ради PASS;
- объявлять DONE без свежей проверки;
- объявлять DONE, пока не пройдены ручные критерии из `npm run trace`:
  зелёный `npm test` закрывает только часть Story;
- расширять scope;
- реализовывать критерии следующих этапов, даже если файлы уже лежат рядом;
- переключать активный этап и править инструменты проверки.
