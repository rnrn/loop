# Установка на пустой компьютер

Всё делается **до занятия**. Во время практической части ничего не
устанавливаем — на это нет времени, и группа разойдётся по разным проблемам.

## Что нужно на самом деле

Мастер-класс **не требует ни одного npm-пакета**. `npm run dev` и `npm test`
работают на голом Node (`node:http`, `node:test`). Поэтому список короткий:

| Что | Зачем | Обязательно |
| --- | --- | --- |
| **Node.js 20+** | dev-сервер и тесты | да |
| **git** | забрать проект | нет, есть ZIP-вариант |
| **Chromium-браузер** | настоящий микрофон и MediaRecorder | да |
| **Coding agent** | собственно агент | да |
| Playwright (~3 МБ) | автопрогон сценария | нет, по желанию |

Размер: Node ~30 МБ, git ~50 МБ, репозиторий меньше мегабайта.
Участнику скачивать больше нечего.

---

Везде одни и те же три шага: **git → Node.js → coding agent**.

## Windows

1. **git** — <https://gitforwindows.org/>
2. **Node.js** — <https://nodejs.org/dist/v24.20.0/node-v24.20.0-x64.msi> (31 МБ)
3. **Claude Code** — в PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Браузер: Edge уже стоит, его достаточно. Chrome — по желанию,
`winget install Google.Chrome`.

**Закройте и откройте терминал заново** после установки Node — иначе `node`
не появится в PATH. Это причина №1 обращений «у меня не работает».

## Linux

1. **git** — из пакетного менеджера:

```bash
sudo apt update && sudo apt install -y git curl      # Debian / Ubuntu
sudo dnf install -y git curl                          # Fedora / RHEL
```

2. **Node.js 20+** — тот же дистрибутив, что и MSI на Windows:

```bash
curl -fsSLO https://nodejs.org/dist/v24.20.0/node-v24.20.0-linux-x64.tar.xz
sudo tar -xJf node-v24.20.0-linux-x64.tar.xz -C /usr/local --strip-components=1
node --version                                        # ожидаем v24.20.0
```

Для ARM замените `linux-x64` на `linux-arm64`.

Альтернатива через пакетный менеджер (nodesource):

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

**Node из штатного apt обычно слишком старый** (в Debian 12 — 18.x), а проекту
нужен 20+. Ставьте tarball или nodesource, иначе `npm test` не запустится.

3. **Claude Code**:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Без sudo.** Установщик ставит агента в `$HOME/.local/bin` и под sudo
откажется работать: иначе бинарник уехал бы в домашнюю папку root, и команда
`claude` не нашлась бы в вашей оболочке. Если каталога нет в PATH:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
```

Установщик сам определяет архитектуру (x64/arm64) и различает glibc и musl,
так что Alpine тоже поддержан. Скачанный бинарник сверяется по SHA256.

Браузер: Chrome или Chromium из репозитория дистрибутива — нужен настоящий
`getUserMedia`, поэтому Firefox для ручного сценария не подойдёт.

## macOS

```bash
brew install git node
brew install --cask google-chrome
curl -fsSL https://claude.ai/install.sh | bash
```

Тот же `install.sh`, без sudo. Для Intel-маков он ставит arm64-сборку под
Rosetta — это ожидаемое поведение установщика.

## После установки — на всех системах

```bash
claude        # первый запуск проводит авторизацию; требует интернета
```

## Проверка

Скрипт ничего не устанавливает, только проверяет. Работает до клонирования
проекта, поэтому его можно разослать заранее вместе с инструкцией.

**Windows:**

```powershell
powershell -ExecutionPolicy Bypass -File setup\check.ps1
```

**macOS / Linux:**

```bash
bash setup/check.sh
```

Ожидаемый результат:

```
[ OK ] Node.js v20.x
[ OK ] npm 10.x
[ OK ] git version 2.x
[ OK ] Браузер: Google Chrome
[ OK ] Аудиоустройство найдено: ...
[ OK ] Coding agent в PATH: claude
[ OK ] Порт 5173 свободен
Ноутбук готов.
```

Красное `[ НЕТ ]` — блокирует занятие. Жёлтое `[ !! ]` — обойдётся
(микрофон заменяется mock-режимом, браузер может лежать нестандартно).

Дальше:

```bash
git clone <url> loop
cd loop
npm run bootstrap
```

## Автопрогон сценария (по желанию)

Прогон ручного сценария в браузере — инструмент модератора. Участнику он не
нужен: Story 1 и Story 2 проходятся руками, как и задумано.

Если всё же хочется поставить участникам, самый дешёвый путь такой:

```bash
npm install          # ~3 МБ, только пакет playwright
npm run scenario:story1
```

**Скачивать Chromium (~150 МБ) обычно не требуется.** Прогон сначала пробует
браузер, который уже стоит в системе:

1. системный Edge — есть на любой Windows;
2. системный Chrome;
3. и только потом Chromium, скачанный playwright-ом.

В выводе видно, что было выбрано: `Браузер: системный Edge`.

Если ни одного браузера нет:

```bash
npx playwright install chromium
```

Участнику, которому автопрогон не нужен, ставить не надо ничего:

```bash
npm run bootstrap -- --participant
```

Этот режим пропускает и `npm install`, и загрузку браузера. `npm test`,
`npm run dev`, `trace`, `gate` и `story` работают на голом Node.

## Что ломается чаще всего

**Агент установлен, но не авторизован.** Проверка видит его в PATH и говорит
`[ OK ]` — а на занятии он попросит войти в аккаунт. Обязательно запустите
агента и выполните любой запрос до занятия. Это главный риск: корпоративный
SSO, MFA и лимиты аккаунта всплывают в самый неподходящий момент.

**PATH не обновился после установки Node.** Терминал нужно перезапустить.
На Windows иногда требуется перелогиниться.

**Микрофон запрещён политикой домена.** Проверьте заранее на реальной
странице с `getUserMedia`. Если запрещён — участник работает через
`?mock-stt=1`, Story и критерии при этом не меняются.

**Корпоративный прокси режет npm или GitHub.** Отсюда ZIP-вариант ниже.

**Порт 5173 занят** другим dev-сервером. `npm run dev` его не отберёт.

## Если сети нет или она режется

Мастер-класс к этому устойчив, потому что зависимостей нет.

1. Модератор скачивает репозиторий и раздаёт ZIP-архивом (флешка, локальная
   шара). `git` при этом не нужен вовсе.
2. Участник распаковывает и работает: `npm run dev` и `npm test` не ходят в сеть.
3. `npm run bootstrap -- --skip-browsers` пропускает Chromium — он нужен только
   для автопрогона сценария, то есть модератору.

Единственное, что действительно требует сети, — сам coding agent.
Установку можно сделать офлайн (ниже), но авторизация без интернета не работает.

## Офлайн-установка Claude Code

### Что делает `irm https://claude.ai/install.ps1 | iex`

Скрипт — тонкий загрузчик, положить его в папку недостаточно: он ходит в сеть
при каждом запуске.

1. Отсекает 32-битную Windows.
2. Определяет платформу: `win32-x64` или `win32-arm64`.
3. `GET .../claude-code-releases/latest` → номер версии.
4. `GET .../{версия}/manifest.json` → SHA256 для платформы.
5. Скачивает `claude.exe` в `%USERPROFILE%\.claude\downloads`.
6. Сверяет SHA256; при расхождении удаляет файл и прекращает установку.
7. Запускает `claude.exe install` — бинарник устанавливает себя сам.
8. Удаляет временный файл.

То есть настоящий артефакт — `claude.exe` (~208 МБ на платформу),
а `install.ps1` лишь находит и проверяет его.

### Подготовка раздачи (модератор, один раз, с интернетом)

```bash
node setup/fetch-claude.mjs                  # обе платформы Windows
node setup/fetch-claude.mjs latest win32-x64 # только x64, если ARM не нужен
node setup/fetch-claude.mjs latest linux-x64 # для Linux-ноутбуков
```

Скрипт делает то же, что официальный установщик — включая сверку SHA256, —
но не устанавливает и не удаляет файл, а складывает в `setup/offline/<версия>/`:

```
setup/offline/2.1.260/
├── manifest.json
├── claude-win32-x64.exe      ~208 МБ
├── claude-win32-arm64.exe    ~208 МБ
└── claude-linux-x64          ~205 МБ
```

Папка в git не попадает (`.gitignore`). Раздаётся флешкой или локальной шарой
вместе с `setup/install-claude-offline.ps1` (Windows) или
`setup/install-claude-offline.sh` (Linux / macOS).

### Установка у участника (без сети)

```powershell
powershell -ExecutionPolicy Bypass -File setup\install-claude-offline.ps1
```

```bash
bash setup/install-claude-offline.sh
```

Скрипт сам определит платформу, сверит SHA256 с локальным манифестом и
запустит установку. Если сумма не совпала — установка отменяется.

### Что офлайн-установка НЕ решает

Авторизация (`claude` при первом запуске) требует интернета: вход в аккаунт,
SSO, MFA. Офлайн-раздача снимает только риск «прокси режет загрузку 208 МБ
на двадцати ноутбуках одновременно» — а он реальный.

Если сети нет совсем, coding agent работать не будет, и занятие не проводится.
Проверяйте доступ к агенту заранее, а не в день занятия.
